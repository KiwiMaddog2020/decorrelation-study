=== SNIPPET 01 ===
Lines 18-20 (seen_keys list membership and index) | performance | Using a list for seen_keys makes each membership check and index lookup O(n), so deduplication is quadratic in the number of events.
Lines 18-20 (deduped[position] = event) | logic | The later event unconditionally replaces the earlier one without comparing the ts field, so out-of-order input keeps an older event instead of the most recent one as documented.
=== SNIPPET 12 ===
Line 26 (return total / contributing) | logic | The result divides by the count of contributing rows instead of the sum of weights, so it is not a weighted average and the weights only scale the numerator.
Lines 18-20 (weight <= 0 check) | boundary | Negative weights are silently skipped rather than rejected, even though the contract says weights are non-negative, which hides invalid input.
=== SNIPPET 14 ===
Lines 21-25 (fingerprint) | logic | The fallback fingerprint omits the query string, the authenticated user or tenant and relevant headers, so distinct requests from different callers with the same path and body collide on one key and may return another caller's stored result.
Line 24 (get_json(silent=True) or {}) | logic | A missing, malformed or non-JSON body is treated as an empty dict, so different invalid or non-JSON bodies all map to the same key and are wrongly deduplicated.
Lines 14-19 (explicit key) | logic | The explicit key is not bound to the request fingerprint, so reusing the same key with a different method, path or body returns a stale result instead of an error, and the key is not scoped per user.
=== SNIPPET 13 ===
Lines 27-29 (granted = " ".join(user.roles); "admin" in granted) | security | The admin check is a substring match on a joined string, so any role merely containing "admin" (for example "sysadmin" or "administrator-readonly") grants full access to every resource.
Line 32 (resource.required_role in granted) | security | The required-role check is also a substring test on the joined string, so a role such as "superuser" satisfies a required role of "user" and an empty required_role always matches, granting unintended access.
=== SNIPPET 09 ===
Lines 30-37 (allow: check outside lock) | concurrency | The availability check and the decrement of self.tokens happen after the lock is released, so concurrent callers can all see the same token count and each consume it, allowing more calls than the budget and letting tokens go negative.
Lines 23-26 (_refill with int() truncation) | logic | Only whole minted tokens are counted and _last is reset to now, so the fractional elapsed time is discarded on each refill and frequent calls at a low rate never accrue tokens, making the effective rate lower than configured.
Lines 17 and 21 (time.time()) | api-misuse | time.time() is a wall clock that can jump backwards or forwards, which corrupts elapsed time and refills; a monotonic clock should be used for interval measurement.
